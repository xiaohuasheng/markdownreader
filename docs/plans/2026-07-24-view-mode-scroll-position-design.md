# 预览与编辑位置同步设计

## 目标

在同一文档的预览模式和编辑模式之间切换时，尽量让用户继续看到原来的内容位置，避免每次切换都回到文档顶部。

## 设计结论

- 预览模式使用窗口滚动，编辑模式使用 `textarea` 内部滚动，两者不能直接复用像素位置。
- 切换前计算当前滚动位置占可滚动范围的比例，切换后按目标模式的可滚动范围恢复相同比例。
- 使用 `0` 到 `1` 的滚动进度覆盖顶部、正文中间和底部；短于可视区域的文档统一定位到顶部。
- 该方案不依赖标题、行号或 Markdown 文本与渲染节点一一对应，适用于无标题长文、表格、代码块和 Mermaid 图表等内容。

## 切换范围

- 点击 `Edit`：记录预览页面进度，渲染编辑框后恢复编辑框内部滚动位置。
- 点击 `Preview`：记录编辑框进度，渲染正文后恢复窗口滚动位置。
- 编辑模式点击 `Save` 并成功返回预览：保存前记录编辑进度，预览渲染后恢复。
- 保存失败或保存期间出现更新的草稿而未返回预览时，取消待恢复状态。

## 边界处理

- 切换文件时清空旧文件的滚动进度，避免把上一份文档的位置应用到新文档。
- 滚动进度和恢复位置均限制在有效范围内，避免负数、超出底部或无效数值。
- 目标模式挂载后再恢复滚动，确保可以取得真实的内容高度和可视区域高度。
- 预览和编辑排版高度差异较大时保证停留在相同比例附近，不承诺对应到完全相同的源码行。

## 验证范围

- 自动化测试覆盖不同高度版式的双向换算、顶部、底部、短文档和无效输入。
- 执行 TypeScript 类型检查、全部测试和生产构建。
- 真实长文档的 `Preview → Edit → Preview`、搜索和保存切换由用户在安装包中手动验证。
