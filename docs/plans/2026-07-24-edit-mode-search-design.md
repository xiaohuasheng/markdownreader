# Edit 模式搜索设计

## 目标

在 Edit 模式中使用 `Command/Ctrl + F` 或 `Find` 时保持当前模式，直接搜索 Markdown 源码，并复用现有固定搜索条的上一处、下一处、计数和关闭操作。

## 根因

原有快捷键和 `Find` 入口显式执行 `changeViewMode('preview')`，搜索匹配只遍历预览区域的渲染 DOM，因此 Edit 模式没有匹配和定位路径。

## 设计结论

- `Command/Ctrl + F` 和 `Find` 只负责打开搜索条，不再改变当前模式。
- 每次通过 `Command/Ctrl + F` 或 `Find` 激活搜索时，输入框都会聚焦并全选已有关键词；直接输入会替换旧关键词，方向键或鼠标操作仍可继续编辑原内容。
- Preview 模式继续使用现有 DOM 高亮，Edit 模式对 `draft` 源码执行忽略大小写的非重叠文本匹配。
- Edit 模式通过 `textarea.setSelectionRange` 保留当前匹配选区，并用与编辑框字体、内边距、自动换行一致的透明镜像层取得匹配的真实纵向位置。
- 当前匹配会滚动到编辑框视口中间，由不接收交互的镜像层覆盖高亮；搜索条同时提示匹配所在行号。
- `Previous`、`Next`、Enter 和 Shift+Enter 共用现有循环切换规则。
- 搜索输入框保持焦点，更新匹配选区时不抢走焦点，保证可以连续输入查询文字。

## 边界处理

- 空查询返回零个匹配。
- 搜索结果会随未保存的 `draft` 实时更新。
- 中文、Markdown 标记和普通英文均按源码内容搜索。
- 匹配滚动位置按实际排版计算并限制在编辑框有效范围内，长短行、表格源码和文档顶部、底部均不会越界。
- 关闭搜索后保留最后一个源码选区，与常见编辑器的查找行为一致。
- 搜索框尚未挂载时，延迟激活逻辑安全忽略，不产生运行时错误。

## 验证范围

- 自动化测试覆盖忽略大小写、多匹配、中文、Markdown 标记、空查询、行号、匹配滚动边界，以及搜索输入框聚焦后全选。
- 执行 TypeScript 类型检查、全部测试和生产构建。
- 安装包中手动验证 Edit 模式不会被 `Command + F` 切到 Preview，以及 Enter、Shift+Enter、Previous、Next 的定位效果。
