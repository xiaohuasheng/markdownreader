# 文件与文件夹打开方式设计

## 目标

打开文件、文件夹或最近记录时，默认不覆盖当前窗口已经显示的内容，而是在新窗口中打开。提供持久化配置，允许用户改为复用并覆盖当前窗口。

## 方案选择

1. 同时保留“当前窗口打开”和“新窗口打开”按钮：入口明确，但首页、工具栏和菜单都会重复，操作负担较大。
2. 仅在首页增加开关：实现简单，但阅读过程中不方便修改，也难以表达菜单和 Finder 打开的行为。
3. 在 `File > Open Behavior` 中提供 `In New Window` 与 `Replace Current Window` 单选项，并由主进程统一路由所有打开入口。

采用方案 3。它不增加 Reader 工具栏复杂度，配置又能在任意窗口访问。

## 配置与窗口状态

- 配置值为 `new-window` 或 `replace-current`，默认 `new-window`。
- 配置保存到 Electron `userData/settings.json`，读取失败或值无效时回退为默认值。
- 主进程记录每个窗口是否已经承载文件、新文件草稿或文件夹。
- 主进程同时维护真实文件路径到窗口的唯一映射；同一个文件再次打开时优先激活已有窗口，不再执行新窗口或覆盖当前窗口的配置分支。
- `new-window` 模式下，目标窗口已有内容时创建新窗口；空白欢迎页仍用于第一次打开，避免遗留无意义的空窗口。
- `replace-current` 模式下，打开操作复用当前聚焦窗口，并继续执行现有监听清理和状态替换。

## 入口行为

- Reader 和欢迎页的 `Open`、`Folder` 使用配置。
- File 菜单的 `Open File`、`Open Folder`、`Open Recent` 使用配置。
- Finder、Open With 和应用启动参数使用配置。
- `Open Folder in New Window` / `New Folder Window` 始终强制创建新窗口，不受配置影响。
- 文件夹侧边栏中切换文件是同一文件夹工作区内的导航，始终在当前窗口完成。
- 文件夹侧边栏、最近记录、菜单、Finder 与应用启动参数均使用相同的文件窗口复用规则。
- `New Markdown File` 保持现有行为，本次只改变“打开文件或文件夹”。

## 异常与边界

- 文件或文件夹选择窗口被取消时不创建空白新窗口。
- 文件读取失败时不改变原窗口内容。
- 新窗口加载完成前通过现有 `sendToRenderer` 延迟投递打开结果。
- 路径使用真实绝对路径比较，避免相对路径或符号链接让同一文件重复打开；并发打开请求等待同一个读取结果。
- 关闭窗口时同步清除窗口占用记录、文件监听和文件夹监听。

## 验证

- 单元测试覆盖默认配置、无效值回退、已有内容时的新窗口路由、空白窗口复用、覆盖模式、等价路径识别和文件窗口登记生命周期。
- 执行 TypeScript 类型检查、全部测试、差异检查和生产构建。
- 生成 arm64 DMG，验证应用签名、DMG 完整性、大小和 SHA-256。
- IOA 可能阻止应用启动，界面与多窗口流程由用户手动验证。
